# Day 5：从 KV Cache 直观理解 MLA

**MLA = Multi-head Latent Attention，多头潜在注意力。**
这里以 DeepSeek-V2 的联合低秩 KV 思路和 DeepSeek-V3 的官方推理代码解释；
不是所有名字带“latent”的 Attention 都有完全相同的实现。

## 1. 你已经理解的 Cache 在存什么

先忽略 RoPE 的特殊处理，普通 Attention 的一个历史 token 会留下：

```text
token t → 当前层隐藏表示 h_t
             ├→ K_t：以后给新的 Q 查询
             └→ V_t：以后给新的 Q 加权汇集
```

多头时，各头通常需要各自的 K/V。序列越长，保存的历史行越多。
GQA 已经做了一步节省：让多个 Query heads 共享较少组 K/V。

## 2. MLA 换了一个问题：能否保存生成 K/V 的短表示

不要先想“压缩文件”，而想“共同材料与多种制作方式”。

```text
一份短材料 c_t
    ├→ 用第0个头的制作方式 → K_0、V_0
    ├→ 用第1个头的制作方式 → K_1、V_1
    ├→ 用第2个头的制作方式 → K_2、V_2
    └→ ...
```

如果各个头的 K/V 本来就是从同一个短向量算出来的，
为什么还要把所有展开结果长期留在 Cache 中？
可以只保留这份短向量，计算时使用学到的投影。

这个短向量就是 `c_t^KV`，latent KV：

```text
h_t → 低维投影 → c_t^KV
                     ├→ Key 的上投影 → 各头的内容 K
                     └→ Value 的上投影 → 各头的 V
```

它不是一句话的文字摘要，不是所有 token 合成一条摘要，
也不是把整个过去“忘掉”。**每层、每个历史 token 都有自己的 latent 向量。**

### 用两个数生成不同头的 K/V

先不考虑位置编码。假设某个历史 token 的短向量是 `c=(a,b)=(2,3)`，
模型学到以下生成规则：

```text
头0：K0 = (a, b, a+b) = (2,3,5)；V0 = (2a, 3b) = (4,9)
头1：K1 = (a+b, a, b) = (5,2,3)；V1 = (3a, 2b) = (6,6)
```

展开保存需要 `2×(3+2)=10` 个数；保存共同来源只要 `(2,3)` 两个数。
**两头的 K/V 不一样，但来自同一份短材料。** 生成规则是全模型共用的权重，
不是为每个历史 token 再存一份规则。

这里的10个数本来就有关联，只由两个数决定，所以两条路径可以等价。
如果给你任意10个独立数字，就不能保证用两个数按这些规则还原；
这正是“架构内的低秩表示”与“任意无损压缩”的区别。

## 3. 公式只看三个

暂用列向量，忽略 Norm 与位置分支：

```text
c_t = W_DKV h_t      # 长表示 → 短 latent
k_t = W_UK c_t       # 短 latent → 各头内容 K
v_t = W_UV c_t       # 短 latent → 各头 V
```

这里的 K/V 是**通过这个结构产生的**，不是先有任意普通 MHA 的 K/V，
再承诺能把它无损塞进更短向量。
训练会让投影与其他参数适应这种表示；不能在现有 Qwen3 上随便添加压缩器就
保证输出和质量不变。低秩约束是一种架构选择，不是免费的可逆压缩。

## 4. 多头还在，和 GQA 有什么区别

```text
GQA：
Q0、Q1 → 直接共享同一组 K0/V0
Q2、Q3 → 直接共享同一组 K1/V1

MLA：
所有头使用共同的 latent 历史
但每个头有自己的投影/查询方式，可产生不同的 K/V 内容表示
```

可以记成：

> GQA 减少独立 K/V heads 的数量；MLA 让多头的 KV 内容表示共享一个低维生成来源。

所以不是把 `n_kv_groups=8` 改为1就成为 MLA。
MLA 改变了状态和投影的数据流，普通 `[B,Hkv,T,D]` 的 Cache 公式不能原样套用。
是否更强/更快需要具体模型和实验，不根据名称得出结论。

## 5. 如果每次都解压全部历史，不是又很慢吗

这一步正是 MLA 的另一个关键：**利用线性计算的结合关系，避免展开全部历史 K/V。**

对某个头的内容部分：

```text
原查询：q · k_t
其中 k_t = W_UK c_t

q^T(W_UK c_t) = (W_UK^T q)^T c_t
```

也就是说，可以先把**当前 Query** 变换到 latent 空间，
再直接与历史 `c_t` 做点积，不必每次为所有历史 token 重建内容 K。
公式里是变换的重排，不是改变相似度算法，也没有删除历史查询过程。

沿用上面的头0：当前 Query 若为 `q=(1,2,1)`，那么：

```text
先展开 K：q·K0 = 1×2 + 2×3 + 1×5 = 13
先改写 Q：q·(a,b,a+b) = 2a+3b
         改写后的 q'=(2,3)，q'·c = 2×2+3×3 = 13
```

只变换当前这一个 Query，就能直接查每个历史 token 的短向量；
不需要先为所有历史位置展开内容 K。这就是“吸收”的直觉。

Value 同样可换顺序。一个头的加权输出：

```text
Σ_t a_t v_t
= Σ_t a_t(W_UV c_t)
= W_UV(Σ_t a_t c_t)
```

先在 latent 空间加权汇集，再投影成输出内容。
官方实现也可以进一步结合输出投影做吸收；具体 kernel 的计算安排需看版本。
矩阵投影是模型共用参数，不是每个历史 token 都另存一套。

**“吸收矩阵”不代表总计算量必定更少。**
保存/读取的状态更小，但算术量、实现效率和硬件表现仍需单独 Benchmark。

## 6. RoPE 不能直接忽略：通常还要缓存位置相关的 Key

如果在完全展开的内容 K 上直接应用位置相关旋转，旋转会夹在矩阵之间，
使上面的简单吸收不再直接成立。
DeepSeek-V2 的解决方式是 **decoupled RoPE（解耦 RoPE）**：

```text
内容路径：q_content ↔ latent KV
位置路径：旋转后的 q_rope ↔ 旋转后的 k_rope
最终分数 = 内容分数 + 位置分数，再按规则缩放/softmax
```

因此紧凑推理路径通常缓存：

```text
c_t^KV：内容 latent
k_t^R：独立的位置 Key
```

不是“只保存一个向量，位置信息就自动解决”，也不是缓存历史 Query。
在采用这类紧凑表示、各层维度相同的前提下，理论数组字节数可写成：

```text
L × B × T × (latent_rank + rope_key_dim) × element_bytes
```

这里没有机械地乘 K/V 两份，因为 `c_t^KV` 是 K/V 联合表示；
另加的是位置 Key。实际分配、padding、量化scale、并行切分仍要另外考虑。

## 7. 同一个小模型，两种算法验证

打开 `learning/day05_mla_intuition.ipynb`。
它不加载 DeepSeek 权重，只用相同的随机低秩参数验证上述等式：

```text
路径A：显式展开各头的 K/V，再 Attention
路径B：缓存 latent + 位置 Key，在 latent 空间打分/汇集
```

教学配置：

```text
4个头
每头内容K维度=4
位置Key维度=2（跨头共享）
每头V维度=3
latent_rank=3
```

若显式物化各头完整 K/V，每 token 保存：

```text
4 × ((4+2)+3) = 36个数
```

紧凑状态每 token 保存：

```text
latent 3 + 位置Key 2 = 5个数
```

这是**同一低秩模型的展开路径与紧凑路径**比较，不是说任意36个独立数都能无损压缩成5个。
这个比值也不是 DeepSeek-V2/V3 的真实配置或通用压缩率。
其中展开路径为每个头拼接位置 Key，因此包含重复的位置数据；
若单独共享位置 Key，展开内容 K/V 加位置 Key 是 `4×(4+3)+2=30` 个数，
仍然不同于紧凑路径的5个数。

实验比较两条路径的 scores、weights 和输出是否在容差内一致。
它不验证训练质量、完整 DeepSeek MLA、生产缓存更新或 GPU加速比。

## 8. 面试主问与参考答案

**问：MLA 是什么？**

> Multi-head Latent Attention。核心是低秩联合表示 K/V，使推理可保存紧凑 latent
> 以及位置相关 Key，而不是各头完整 K/V；利用矩阵吸收，在 latent 空间查询/汇集。

**问：与 GQA 有什么区别？**

> GQA 通过减少独立 KV heads 让 Q 分组共享；MLA 改变 KV 的生成和缓存表示，
> 多头内容可以由共同 latent 加不同投影得到，不是只改 heads 数。

**问：解压历史是否抵消节省？**

> 朴素展开路径可能有成本；吸收/重排可以避免物化所有历史内容 K/V，
> 但实际算术和kernel性能仍要实测，不保证所有场景更快。

**问：压缩是否无损？**

> 任意普通模型转成低秩结构不保证无损。这里能证明的是同一套已经定义为低秩的
> 参数，在展开和吸收两种计算顺序下数学等价，浮点仍有误差。

**问：MoE 与 MLA 为什么能一起用？**

> MoE 改变 FFN 的专家路由，MLA 改变 Attention 的 KV 表示，作用在不同模块。

## 9. 读官方代码时对应哪些名字

DeepSeek-V3 官方 `inference/model.py` 中，先看 `class MLA` 的 `absorb` 路径：

| 代码名称 | 这里的含义 |
| --- | --- |
| `kv_lora_rank` | 每个 token 的联合 KV latent 宽度，不是 KV heads 数 |
| `qk_nope_head_dim` | 每个头不做 RoPE 的内容 Q/K 宽度 |
| `qk_rope_head_dim` | 单独做 RoPE 的 Q/K 宽度 |
| `v_head_dim` | 每个头展开后的 V 宽度 |
| `kv_cache` | 历史 latent，代码中缓存的是经 `kv_norm` 后的表示 |
| `pe_cache` | 历史位置 Key |
| `wkv_b` | 各头内容 K/V 的上投影权重，吸收路径不必展开完整历史 |

逻辑形状可读成每层 `kv_cache=[B,T,rank]`、`pe_cache=[B,T,rope_dim]`；
官方示例预分配的是最大 Batch/长度，并按有效前缀读取。
不要因为名字中带 `lora` 就理解为“只在推理时加的 LoRA 微调适配器”；
这里是 MLA 架构内部的低秩路径维度。
