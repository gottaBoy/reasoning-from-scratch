# Day 29：把实验写成别人能复现的报告，而不只是“跑通了”

前置：[Day 14](DAY14_MODEL_BASELINE.md)、[Day 27](DAY27_METRICS_BENCHMARK.md)。

## 1. 图解与数字例子

把报告看成实验交接单：

```text
问题 → 假设 → 固定输入与环境 → 修改一个量
     → 正确性 → 实测原始结果 → 限制与失败 → 下一步
```

“更快20%”没有说比较对象和时间口径，不能复现。
假设基线10ms、优化8ms，耗时降低20%，加速比1.25x；
二者不是“快了25%”可以随意混用的同一指标，写出公式最清楚。
这是算术示例，不是本仓库某个kernel的实测。

## 2. 概念与计算契约

代码版本、硬件/驱动、torch/triton、模型来源/精度、输入shape/seed、
测试oracle与阈值、预热/重复/同步、原始日志与错误缺一不可。
模型质量、数学正确、性能提升三种证据不能互相代替。
随机小模型token ID不用于语言质量，mock HTTP不用于真实服务容量。

当前 `run_day(29)`只给环境与模板字段；不是已替你完成技术报告。
哪些字段自动采集、哪些是个人假设/解释，分别标明。

## 3. Jupyter与源码路线

打开 [Day 29 Notebook](../learning/day29_course.ipynb)，按模板填写自己的一个已运行实验。
优先选择范围小且证据齐全的例子：一个Mask错误、非连续页、某tile变慢。
复用 [Mini引擎报告模板](../learning/mini_vllm/README.md) 与
[历史验证记录](COURSE_VALIDATION.md) 的日志/限制分栏方式。

用新目录保存原始报告，引用具体命令与源码位置；
模型不能提交时提供合法来源、版本/hash与转换步骤，不上传访问令牌。

## 4. 调试与优化顺序

1. 让另一个干净进程按命令重跑，不依赖Notebook旧变量。
2. 核对输入/shape/统计口径，区分启动与稳态、模拟与实测。
3. 对失败保留traceback和原始配置，不只留下最终成功截图。
4. 逐项标记passed/skipped/依赖未满足，不能看“Notebook执行完”就全算通过。
5. 报告下一条可证伪的假设，而不是同时加入量化、多卡、分页等所有技术。

AI可协助整理、生成测试与查源码；算法结论仍需实验支撑，并标明你的独立贡献。

## 5. 自测与参考答案

**问：10ms降到8ms怎么算？**
答：耗时下降(10-8)/10=20%，加速比10/8=1.25x，明确单位与口径。

**问：没有权重文件能复现吗？**
答：可给合法来源、精确身份与下载/转换步骤；随机教学模型可给配置和种子。

**问：测试全部通过代表性能一定提升吗？**
答：不代表，正确性与性能是独立证据。

**问：AI写了代码能直接写“我完成优化”吗？**
答：应说明独立分析、实现/验证部分与AI协助，结论依可复现数据而非生成来源。
